## 3.1 准备材料与官方入口

先准备一台 Windows 电脑、能访问所选模型服务的网络，以及一份历史题面 PDF/Word。第一次建议只跑历史题练习：先把配置、求解和导出跑通，再考虑正式比赛的当届规则与 AI 披露要求。通用准备方法见[数模总教程](../docs/math-modeling.md)。

| 入口 | 用途 |
| --- | --- |
| [Modex 官网](https://www.mingheng.xin/) | 下载、使用手册与产品更新入口 |
| [官网提供的 Windows 下载分享](https://pan.baidu.com/s/1XN1OKUL2gtg71gDr6JpZCA?pwd=wt5k) | 提取码 `wt5k`；链接失效时回官网重新进入 |
| [官方《Modex Agent 使用手册》](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF) | 配置截图、模型预设、使用注意事项 |
| [官方配置视频](https://v.douyin.com/7lVtqkZQUI0/) | 手册所附配置演示；本项目未观看核验 |
| [官方问题反馈](https://github.com/N-allpass/modex-mh-agent/issues) | 查看或提交可复现的问题 |

核查时，下载分享展示的文件为 **`Modex-MH-Agent Setup 2.1.2.exe`**，大小 **1,396,976,347 字节，约 1.40 GB**，分享文件修改时间为 **2026-09-26**。这是分享中的安装包名称，不代表已经验证的运行版本，也不保证没有更新的应用内增量更新。[官方下载分享](https://pan.baidu.com/s/1XN1OKUL2gtg71gDr6JpZCA?pwd=wt5k)

官方称安装包带有 Python、Node、Claude CLI 和排版等工具，但 README 与官网对 TeX 组件的写法不同。先按安装程序操作，遇到实际缺失再补依赖；不要为了本教程预先安装一整套重复环境。官方资料未明确完整的 Windows 版本、内存和磁盘最低要求；安装包大小也不等于安装后的占用。[官方仓库](https://github.com/N-allpass/modex-mh-agent)、[官网](https://www.mingheng.xin/)

## 3.2 下载、安装与首次打开

1. 从官网进入 Windows 下载，或打开上面的官方分享，核对文件名后下载。下载入口发生变化时，以官网新链接为准。
2. 运行安装程序，按提示选择安装位置。官方 README 建议避免过深路径及包含特殊字符的目录；可以选择自己容易找到、权限正常的简短目录。
3. 首次打开后，先记下界面显示的应用版本。若出现更新提示，阅读更新说明，再决定是否更新；不要把分享包版本直接写成当前应用版本。
4. 若出现激活或授权页面，按该页面与官方渠道的说明处理。官方手册提到免费激活码，但本项目未核实可领取方式、有效码、试用限制或是否必须激活。软件授权与模型服务用量是两回事，不能据此推断软件免费或付费。
5. 打开右上角设置，先完成下一节的模型配置，再创建完整任务。[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)

如果系统拦截安装，先核对来源、文件属性及发布者信息，再按实际提示查原因。本项目没有核验安装包签名或散列，不提供关闭系统保护的安装步骤。

## 3.3 配置模型连接：先确认你走的是哪条路线

**官方资料对模型接入的描述存在差异，不能直接承诺现有 API Key 可以通用。** README 写的是 Claude/Claude Code 执行器，加上独立的 OpenAI 兼容评审 API；官方手册则描述合作中转、限制自定义 URL、渠道分组与模型预设。手册早于本次看到的安装包，2.1.2 实际是否仍有 URL 限制，本项目没有查看界面确认。[官方仓库](https://github.com/N-allpass/modex-mh-agent)、[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)

因此，先看设置页：如果只能通过指定入口取 Key、选分组和预设，就按下面的手册路线配置；如果当前版本明确允许自定义服务，再使用它实际支持的协议、地址和认证方式。不要把一个聊天订阅、已有服务账号或另一家平台的 Key 自动当成可用额度。

### 按官方手册连接服务

1. **打开右上角设置。** 找到获取 API Key 的入口，先阅读它指向的服务说明。手册描述的是软件之外的服务账号。
2. **在该服务完成所需的注册或登录。** 阅读当前渠道、价格与计费单位，再创建 API Key。本篇没有代办账号或充值，也不提供通用 Key。
3. **创建 Key 时选对渠道分组。** 手册把不同模型路线放在不同分组中；分组、Key 与模型预设必须配套。不能只看模型名称相似就混用。
4. **回到 Modex，添加模型预设。** 手册使用“添加预设／模型预设库”入口，按所选渠道添加预设并核对模型 ID。界面提供现成预设时，先用当前预设，别凭记忆手填一个模型名。
5. **按当前预设要求填写 Key 等连接信息，然后保存。** 有服务地址字段时，填该服务要求的 API 地址；不要填官网登录页或聊天网页地址。
6. **使用设置中的连接测试。** 先验证所选服务能连接，再给完整工作流分配模型。Key、分组或模型 ID 任一处不匹配，都应先处理报错。
7. **确认可用额度及计费方式。** 手册描述了钱包充值流程；是否需要充值、已有余额能否覆盖测试，以当前服务页面为准。不要在尚未连通、尚未理解单位时直接启动整篇任务。[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)、[官方仓库](https://github.com/N-allpass/modex-mh-agent)

手册中的渠道名称可以帮助定位，但不代表这些渠道今天仍然存在：

| 手册所述用途 | 手册中的渠道分组 | 配置时要核对的内容 |
| --- | --- | --- |
| Claude 路线 | `claude code kiro` | 当前可用预设、模型 ID 与服务说明 |
| DeepSeek 路线 | `DeepSeek官转渠道` | 该分组配套的 Key 与模型预设 |
| GPT 路线 | `Codex转Claude code` | 手册使用中转别名，不能把别名当成官方模型身份认证 |
| Grok 路线 | `Grok build to claude` | 手册中的版本说法有不一致，先看当前渠道与预设 |
| 可选 image2 功能 | `default` | 手册要求在图片设置中另配令牌；第一次跑通建模可先不启用 |

这里不照抄手册中的“某个 Claude 名称对应某个 GPT 后端”映射，因为本项目未验证中转当前提供的模型及其身份。先以当前服务可用性和实际测试为准。[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)

### 分配预设：保存 Key 之后还有一步

手册描述了两处分配方法：在**工作流设置底部，为界面列出的三个角色分别选择预设**；或者在**新建工作流底部，为具体步骤选择预设**。只新增预设、没有把它分配给角色或步骤，未必完成了任务配置。[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)

按下面顺序检查即可：

1. 预设库里能看到刚添加的预设。
2. 该预设的 Key、渠道和模型 ID 已保存，连接测试通过。
3. 工作流中的各角色已有对应预设；若逐步骤指定，逐项查看是否仍选着旧预设。
4. 保存工作流设置，再开始小任务。

官方宣传执行与评审分工：执行端产出内容，评审端提意见，再交回修改。这能提供检查机会，但评审通过或分数上涨不能代替你重跑代码、核对公式和查证引用。[官方仓库](https://github.com/N-allpass/modex-mh-agent)

## 3.4 两组模式不要混淆

| 选择项 | 官方描述 | 第一次练习怎么选 |
| --- | --- | --- |
| 全自动 / 协同 | 官网把它们用于人与工作流的交互：全自动按流程推进，检查点仍会暂停；协同在执行前与用户讨论 | 优先协同，先看它如何理解题目和制定方案 |
| 严格 / 省额度 | 手册另行描述的执行与额度选项，尤其提到优化类题目 | 先用省额度做小范围验证；需要扩大搜索或复核时，再阅读当前模式说明后调整 |

这两组开关不是同一回事。“全自动”不表示整场任务无需人工确认，“省额度”也不构成费用上限。本项目没有比较过它们的质量、耗时或花费。[官网](https://www.mingheng.xin/)、[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)

官方 README 明确软件不附模型额度，模型调用由所选服务计费。手册的一些成本举例使用“额度”而没有说明货币单位，不能直接换算成“每篇多少元”。启动前查看当前渠道单价、余额、可设置的预算与评审轮数；优先跑单步，再判断是否继续。[官方仓库](https://github.com/N-allpass/modex-mh-agent)、[官方手册](https://docs.qq.com/doc/DQk1LZWtBaFhRd0VF)

## 3.5 新建任务并输入赛题

官方描述的竞赛流程大体是：读题与拆解 → 建模与求解 → 编程、实验和图表 → 论文写作 → 编译与格式检查。你可以把它看成带检查点的项目，而不是一次把题目发给聊天框。[官方仓库](https://github.com/N-allpass/modex-mh-agent)

1. **新建工作流，选择竞赛类模板。** 本篇历史题练习选择全国大学生数学建模竞赛／CUMCM，语言选中文；名称以实际界面为准。
2. **上传官方题面 PDF/Word 与全部必要附件。** 官方称能提取文本。扫描件、公式、表格和附件是否读对，需要你检查；不要只贴题目标题。
3. **补充任务约束。** 写清题目年份、题号、全部问题、结果口径、允许使用的数据，以及希望何时暂停。没有附件时明确说明，禁止它补造附件。
4. **选择预设、交互模式和迭代选项。** 首次推荐协同，并先限制为完成读题与方案；不要一上来就启用大量循环。
5. **检查它提取的题意和数据。** 表格行数、百分数、单位、检测费用、次品率等关键数字都应与原 PDF 对照，再批准求解。[官方仓库](https://github.com/N-allpass/modex-mh-agent)

README 中的页数与模板是产品预设，不是已经核实的当届参赛要求。正式使用时，页数、匿名信息、文件格式及 AI 使用声明都按当届比赛通知调整。

### 可直接复制：2024 国赛 B 中文四问启动任务

先上传 **2024 年全国大学生数学建模竞赛 B 题《生产过程中的决策问题》官方题面 PDF**。下面是一条练习任务，不附带现成答案，也不代表 Modex 已在本项目中跑过这道题；可与[本项目的历史题运行记录](../examples/cumcm2024b/README.md)对照阅读。

```text
请用我上传的 2024 年全国大学生数学建模竞赛 B 题
《生产过程中的决策问题》官方 PDF，建立一个中文历史题练习工作流。
这次先完成读题、四问拆解和可验证的建模方案，等我确认后再求解和写论文。

先逐项核对 PDF 的题干、表格、数字、单位和四问要求，列出数据来源与疑点。
没有提供的附件、实验数据、参考文献和运行结果不得编造。
若读不清公式或表格，指出位置并暂停等待我补充。

四问都要覆盖：
1. 抽样检验：按原题分别处理拒收与接收的判断要求，明确假设、
   置信要求、样本量和判定阈值，解释方案如何降低检验成本。
2. 两个零配件到成品：按题面各情形比较零配件检测、成品检测、
   不合格成品拆解等决策。先写清成本、收入、损失及拆解回流口径，
   再给出策略比较表；用可复算程序和至少一个手算例子检查结果。
3. 多工序、多零配件：先说明如何推广问题 2 的状态与决策，
   再求解原题给定情形，说明拆解回流、终止条件、计算方法和验证办法。
4. 次品率由抽样得到：承接问题 1 的统计估计，重新讨论问题 2、3，
   区分点估计与估计不确定性，报告策略变化及敏感性。

每问都要交付：假设和符号、数学模型、求解步骤、可运行代码、
关键结果表、与结果一致的图、验证或敏感性分析及局限。
随机方法固定种子；表格和图的数值必须来自实际运行。
有多种成本或返工解释时，先列出差异让我确认，不擅自选定。

检查点设在：题意与数据确认后、模型方案完成后、求解与验证完成后、
论文大纲完成后、最终导出前。每次用几句话说明已完成什么、
证据在哪、尚有什么疑点，再等我继续。

确认求解后，先整理可复现代码与数据，再形成中文论文。
输出正文、代码、图表和运行说明，最后报告软件实际生成或导出的路径；
任何尚未运行、编译失败或未核实的内容必须明确标注。
```

## 3.6 到检查点时，具体看什么

官方 README 描述了继续、提交修改意见和单步重跑等操作。不要只因为进度条完成就点下一步，可以按下面的顺序验收。[官方仓库](https://github.com/N-allpass/modex-mh-agent)

| 检查点 | 你要看到的东西 | 常见返工要求 |
| --- | --- | --- |
| 读题之后 | 四问完整；数据表、单位与原文对应 | “第 2 问少了拆解决策，请重新拆题，暂不写论文。” |
| 建模之后 | 目标函数、约束、假设与成本口径清楚 | “请解释拆解回流如何计费，并用小例子检查是否重复记账。” |
| 求解之后 | 实际运行记录、结果表、至少一种独立复核 | “先给可复算结果和边界测试，暂不把未验证数字写入正文。” |
| 写作之前 | 每问结果均已落实，图表与论点能对应 | “先补第 4 问的不确定性分析，再拟摘要。” |
| 导出之前 | 全文、引用、图表、公式和附件完整 | “列出未解决项，修正后重新编译并说明变化。” |

修改意见尽量带上“哪一步、哪里有问题、依据是什么、改完怎么验收”。例如：“问题 2 的表格第 3 种情形与代码输出不一致，请从程序实际结果更新表格和正文，并解释差异。”

## 3.7 失败恢复：先定位，再决定重跑范围

看到任务不动时，先看状态和日志。**等待检查点确认**与**执行报错**是两种状态：前者需要你继续或提出修改意见，后者需要先处理原因。官方描述支持单步重跑；实际入口与可恢复范围以当前界面为准。[官方仓库](https://github.com/N-allpass/modex-mh-agent)

1. 记下失败的步骤、时间、所用预设，以及错误文字。
2. 查看此前步骤的产物是否仍在，保存你需要保留的文件和修改。
3. 分清连接、额度、程序、数据或编译问题，按下一节处理。
4. 能定位到单步时，先修正输入或设置，再只重跑该步；跨步骤修改数据或模型后，相关图表、结论和正文也要重新生成并核对。
5. 不确定是否已发生计费时，先查看服务用量记录，避免反复点击启动。

上面是建议的排查顺序，并非本项目验证过的自动恢复机制。不要假设重启应用后一定会从原位置继续。

## 3.8 编译、编辑与导出

官方介绍内置文件树、LaTeX 编辑与 PDF 预览，支持编译；官网还介绍了修复模板、对话修改及撤销等功能。README 也提到 `output_format=docx` 的 Word 输出路线并跳过 LaTeX 编译，但本项目没有核实当前界面如何设置这个选项。[官方仓库](https://github.com/N-allpass/modex-mh-agent)、[官网](https://www.mingheng.xin/)

按下面顺序收尾：

1. **先保存项目。** 在产物列表或文件树确认论文、图表和代码都能打开。
2. **选择目标格式。** 需要 PDF 时检查 LaTeX 与模板，执行编译；需要 Word 时使用当前版本提供的 Word 输出选项，不要凭本篇假定某个配置框必然存在。
3. **处理编译错误。** 查看日志中的首个实际错误；模板问题可查看当前界面是否有“修复模板”入口。修改后重新编译，确认 PDF 是本次生成的版本。
4. **逐页查看成稿。** 检查空白页、公式截断、表格越界、中文字体、图例、引用与摘要数字。Word 导出也要重新打开查看，不能只检查文件是否存在。
5. **导出并记录真实路径。** 从软件实际提供的产物、导出或打开文件夹入口取得位置。本篇不预设 `outputs/`、论文文件名或软件的默认目录。
