## 6.1 先挑有输入、有评分表、能验收的作品

先拿到当届赛题、评分表和提交清单。别先让 Agent 做一个大而全的产品：先确认输入数据、接口、平台与演示环境可用，再把一个评分动作从头跑通。

| 先问什么 | 你需要拿到什么 |
| --- | --- |
| 评委按什么打分？ | 评分点 → 验收动作 → 对应文件或演示位置 |
| 数据、SDK、接口从哪来？ | 可实际读取的数据、可运行的官方示例或接口响应 |
| 最小作品交什么？ | 一个真实输入、一条完整业务链、一个可以检查的输出 |
| 工具范围是什么？ | 当届允许的开发方式、模型/平台要求和声明位置 |

计设与软件杯都适合用编码 Agent 推进开发，但本项目没有核到覆盖所有赛项的外部 Codex 许可；按下面的具体赛事卡确认范围再开工。

**复制给 Codex：开打**

~~~text
我要做中国大学生计算机设计大赛软件作品。inputs/ 有当届规程、赛道要求和真实需求。先输出工具权限与评分项对照表：2026规程限制AI工具范围，不能默认Codex在名单内。用于赛前练习，或确认当前参赛范围允许后，用 $frontend-design 完成一个单一核心功能的可运行系统；用 $webapp-testing 测正常、空输入和异常场景。交付实际运行视频、源码、部署说明和过程材料；演示必须来自同一版本，别只做PPT。
~~~

**需要交出来：** 可运行作品、完整源码、部署入口、测试截图、真实演示和说明。

**你仍需要完成：** 原创选题与内容判断；合规工具及过程记录；真机/部署测试与答辩。

## 6.4 先验收一个评分动作，再扩大范围

先让 Agent 交出：能启动的程序、固定输入样本、对应输出、启动命令与一条可重复的验收过程。一个评分动作跑通后再加第二个，每次保留之前已通过的结果。

~~~text
先只完成评分表中最关键的一条业务链。把输入、操作、期望输出和实际结果写进验收记录；保存可运行版本。
通过后再扩展功能。完成前请在干净环境按 README 启动，核对异常输入、演示路径和失败提示。
最后把评分表逐条映射到测试、截图或演示时间点；未完成的项明确列出来。
~~~

有了可运行产品后，继续看[第 9 章：演示、答辩与提交](09-演示、答辩与提交.md)。想找同类赛事，打开[全部赛事目录](../docs/competition-catalog.md)，逐项读数据、设备和人工门槛。
