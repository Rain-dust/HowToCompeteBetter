## 7.1 先确认你的 RST 属于哪一种评审

RST 不是一种统一的交付方式。同一母赛下先确认届次、赛道和组别，再决定如何使用编码 Agent。

| 具体类型 | 第一件事 | 用什么证明做到了 |
| --- | --- | --- |
| 创新创业作品 | 对评分表做一个可运行的小产品 | 功能演示、真实输入输出与说明 |
| 仿真竞技 | 安装对应官方平台，运行原始基线 | 原始策略、环境版本、原始成绩与日志 |
| 硬件竞技 | 确认器材、维护、场地和现场要求 | 同设备实测与可复现的现场操作 |

本项目作者的省奖经历是**第 18 届创新创业赛道—前沿技术挑战组**；外部 Gemini 机器鱼国一自述来自第 19 届另一赛项。两者不能合成所有 RST 赛项都已跑通的证明。

## 7.2 工具与完整启动任务

**先进机器人及仿真技术大赛（RST）：先定赛项，再跑官方基线。**

创新作品、仿真竞技和硬件赛分别核平台及AI范围；已熟悉平台者再比较投入。

[完整赛事卡](../docs/contests/N18.md) · 规则资料核查至 2026-11-12

**对应工具仓库**

- [创新软件作品可用技能](https://github.com/anthropics/skills)
- [可替代Codex的独立编程agent：Cline](https://github.com/cline/cline)

**复制给 Codex：安装与预检**

~~~text
先读 inputs/ 的具体RST届次、赛项、平台和SDK。仿真竞技先配置官方环境并运行基线，不预装无关网页技能。只有创新作品确实需要Web界面时，才从 https://github.com/anthropics/skills 完整安装 frontend-design 与 webapp-testing 到项目 .agents/skills/ 并做最小验证。报告实际平台版本、基线成绩、日志和缺失依赖。
~~~

**复制给 Codex：开打**

~~~text
我要参加RST，具体届次、赛道、组别、官方规则和平台SDK已放 inputs/。先识别这是创新创业作品还是仿真竞技，不能混用评审方式。创新作品：完成一个能运行并按评分点演示的小产品；仿真：先跑官方基线、记录多次成绩，再逐项改策略，输出同环境的对照、失败回放和日志。按我的具体组别整理源码、说明、视频与答辩。官方基线未跑通前先修环境，不虚构成绩。
~~~

**需要交出来：** 对应赛项的程序/策略、实测日志与对照、视频、说明与答辩包。

**你仍需要完成：** 官方平台和SDK调通；仿真有效性与重复测试；对应组别的实际演示与答辩。

## 7.3 把基线、改动与失败留在同一套环境里

先保存官方基线版本和原始成绩，再做可单独撤回的小改动。对照时保持平台、输入和评测条件一致，保留多次运行结果与失败回放，不只挑最好的一次。

~~~text
先复现官方基线，不修改策略。记录平台和 SDK 版本、启动命令、输入、成绩及完整日志。
基线跑通后，每轮只改一项策略；在相同条件下与基线重复比较，汇总每次成绩与失败原因。
保留能够回退的代码、失败回放和环境说明。未实际运行的结果不能填成成绩。
~~~

这里没有提供经核验的 RST 专用保奖 skill。创新作品需要 Web 界面时才选界面技能；仿真策略应让 Codex 读取实际平台和 SDK，不能用网页模板代替。
